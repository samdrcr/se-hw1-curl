📌 Learning Objectives

This assignment strips away the magic of modern HTTP clients. By bypassing high-level libraries like requests, axios, or fetch, we are forced to confront the reality of network programming:

  • Network Layers: Understanding how application data (HTTP) is ferried across transport streams (TCP) and secured by encryption protocols (TLS).
  • Protocol Formatting: Realizing that HTTP is entirely defined by strict plain-text syntax, relying heavily on carriage returns and line feeds (\r\n).
  • Stream Processing: Handling continuous byte streams, detecting boundaries, and decoding chunked hexadecimal payloads in real-time.

🧰 Dual-Language Architecture

To prove that the underlying network mechanics are independent of any specific programming language, this project features two distinct implementations:

🐍 Python (v1: Synchronous)

Powered by: socket + ssl

This implementation uses a traditional blocking I/O model. It opens a socket, wraps it in an SSL context, and sequentially waits for data to arrive. It highlights imperative byte-array manipulation and stateful loops for parsing headers and chunks.

⚡ TypeScript (v2: Asynchronous)

Powered by: net + tls

This version leverages Node.js's event-driven architecture. Instead of waiting, it attaches listeners to data and end events. It showcases non-blocking memory management using raw binary Buffer objects and slice pointers.

🧬 The Lifecycle of a Request

When you execute one of the scripts, the following sequence occurs beneath the surface:

  • 1
    DNS Resolution: The hostname (e.g., jsonplaceholder.typicode.com) is resolved to an IP address.
  • 2
    TCP Handshake: A reliable stream is established over Port 80 (HTTP) or Port 443 (HTTPS).
  • 3
    TLS Negotiation: If HTTPS is used, client and server agree on cipher suites and exchange certificates to encrypt the socket.
  • 4
    HTTP Request: The client pushes an exact byte-encoded string across the wire.
  • 5
    HTTP Response: The server replies with a status code, headers, and the payload body.

🔍 Inspecting the Raw Data

The Request String

This is the exact plain-text block our programs inject into the TCP socket:

GET /posts/1 HTTP/1.1\r\n
Host: jsonplaceholder.typicode.com\r\n
User-Agent: RawCurl/1.0\r\n
Accept: application/json, */*\r\n
Connection: close\r\n
\r\n

Decoding "Transfer-Encoding: chunked"

Because we don't use high-level tools, we must manually parse chunked bodies. The server sends data prefixed with the chunk size in hexadecimal:

1bf\r\n                 <-- Hex for 447 bytes
{"userId": 1, ...}\r\n  <-- The actual JSON data
0\r\n                   <-- Zero means the stream is finished
\r\n

Both our Python and TypeScript clients include custom algorithms to detect the \r\n boundaries, convert the hex size to an integer, extract the exact number of bytes, and reconstruct the full JSON file seamlessly.
